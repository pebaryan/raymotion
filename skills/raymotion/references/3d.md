# GPU 3D scenes (`g3d::`, `rmtn/scene3d.hpp`)

Three.js-style scenes drawn by a timeline node. Right-handed, +y up, rotations are
Euler XYZ in degrees, colours are sRGB. Geometry, models and textures load on first
draw, so build scenes while registering. Every `up` must set absolute values from `t`.

```cpp
auto scene = std::make_shared<g3d::Scene>();
scene->camera.position = { 0, 3, 8 };
scene->camera.target = { 0, 1, 0 };
scene->camera.fov = 40;                                    // vertical degrees; or orthographic + orthoHeight

g3d::Material floor{ mkColor(0x30364a), 0.9f };             // colour, roughness
scene->add(g3d::Geometry::plane(20, 20), floor);
g3d::Material teal{ mkColor(0x47dad8), 0.25f };
teal.metalness = 0.3f;
g3d::Object3D* knot = scene->add(g3d::Geometry::knot(1, 0.35f), teal);
knot->position = { 0, 1.5f, 0 };
knot->up = [](int t, g3d::Object3D& o) { o.rotation = { 0, t * 2.f, 0 }; };

scene->lights.push_back(g3d::Light::directional({ -6, 12, 5 }, WHITE, 1.1f, /*shadow*/ true));
scene->lights.push_back(g3d::Light::point({ 2, 3, 2 }, ORANGE, 2, /*range*/ 10));
scene->lights.push_back(g3d::Light::spot({ 6, 7, 6 }, { 0, 0, 0 }, WHITE, 2, /*outer deg*/ 24, true));

addRoot(c.roots, 0, 240)->fn = g3d::draw(scene);                       // whole frame
addRoot(c.roots, 0, 240)->fn = g3d::draw(scene, { 1340, 700, 520, 320 }, topCam);   // inset, other camera
```

- **Geometry:** `box(w, h, d)`, `sphere(r)`, `plane(w, d)` (faces +y), `cylinder(r, h)`,
  `cone(r, h)`, `torus(r, tube)`, `knot(r, tube)`, or your own
  `std::make_shared<g3d::Geometry>([] { return someRaylibMesh; })`.
- **Models:** `scene->add(g3d::loadModel("robot.glb"))` (glTF/GLB, OBJ, IQM, M3D, VOX);
  skeletal animation through `obj->animation` (index) and `obj->animationFrame`.
- **Hierarchy:** `Object3D* g = scene->add();` makes an empty group, and `g->add(...)` adds
  children. `visible = false` hides a subtree. `scene->find("name")` finds an object by name.
- **Materials:** `color`, `roughness`, `metalness`, `emissive`, `opacity` (< 1 sorts
  transparent objects), `unlit`, `doubleSided`, `castShadow`/`receiveShadow`, `map`
  (texture file).
- **Lights:** up to 8 lights. Directional, point and spot lights can all cast shadows
  (`shadowExtent`, `shadowBias`, `scene->shadowMapSize`).
- **Ambient light:** `skyColor`/`groundColor`/`ambient`, or image-based lighting:
  `scene->environment = "studio.hdr"` or
  `scene->environmentGenerator = g3d::studioEnvironment(top, horizon, bottom)`
  (`showEnvironment` draws it as the backdrop).
- **Sky:** `scene->sky = g3d::Sky::at(hour)` (or `day()`, `dawn()`, `dusk()`, `night()`,
  `Sky::mix(a, b, t)`) draws a procedural backdrop (gradient, sun, stars, drifting clouds)
  that also lights and reflects like an environment. Fields: `zenith`, `horizon`,
  `ground`, `sunDirection` (or `sunLight = i` to follow light i), `sunSize`, `sunGlow`,
  `stars`, `clouds`, `cloudDrift` (per frame), `lighting`, `show` (false: light only).
  Set it in `scene->up` to animate the time of day.
- **Fog and background:** linear `fogColor`, `fogNear`, `fogFar`; or
  `fogMode = g3d::FogMode::Exponential` (or `Exponential2`) with `fogDensity`, plus
  `fogHeight`/`fogFalloff` for ground fog that thins with height; `fogFromSky = true`
  takes the sky's colour per direction. `background` (BLANK lets the 2D content beneath
  show through).
- **Camera:** `camera.dof = { focusDistance, aperture, maxBlur, tilt }` blurs by depth;
  `tilt` (degrees) leans the plane of focus: negative for the tilt-shift miniature look
  (a high camera looking down, focus on the subject), positive to keep receding ground
  sharp. A camera can have its own `up` to move it.

Camera framing: a subject of radius `r` fills about half the frame height at distance
`d ≈ 2 * r / tan(fov / 2)`. Check framing with a still before rendering.

## Particles in a scene

`fx::Emitter3D` (`rmtn/particles.hpp`) is the 2D emitter in world units (speeds per
frame, gravity per frame squared, +y up). Add it to the scene or an object; particles
live in that object's space:

```cpp
camp->add(fx::fire3d(0.26f))->position = { 0, 0.12f, 0 };   // smoke3d, embers3d alongside
fx::Emitter3D shell = fx::burst3d(260, { PINK, GOLD });
shell.burstAt = 160;                                          // local frame of the scene node
scene->add(shell)->position = { 0, 7, -5 };
fx::Emitter3D chunks = fx::debris3d(46);                      // floor = true: lands and rests
scene->add(chunks, g3d::Geometry::box(1, 0.6f, 0.8f), crateMaterial);   // mesh particles
```

- Billboards (`Dot`, `Glow`, `Star`, `Ring`), `Streak` along the motion, `Square` and
  `Confetti` as tumbling quads; `additive` for fire, sparks and fireworks. They are
  depth-tested against meshes and fogged, but cast no shadows; light them with a point
  light of their own (a flickering `up` on its intensity sells a fire).
- With a geometry, particles are lit mesh instances (shadows, ink lines); the emitter
  object's geometry itself is not drawn. `size` scales the geometry.
- `area` = `Volume::Point/Line/Box/Sphere/Shell/Disc/Ring` (`extent`; disc and ring lie on
  the ground); `direction` + `spread` (full cone angle; 360 = all round) or `outward`;
  `origin(frame)` for a moving source such as a rocket's trail.
- Presets: `burst3d`, `sparks3d`, `fountain3d`, `confetti3d`, `snow3d`, `rain3d`,
  `fire3d`, `smoke3d`, `embers3d`, `debris3d`. Sizes assume about a metre per unit.
- `fx::particles(e, t)` gives the live `Particle3D`s for anything custom.

## Characters (`rig::`, `rmtn/rig.hpp`)

One skeleton, many bodies. Motion lives in the skeleton (clips are pure functions of
time). Parts, outfit and face are a `Look`. One `Character` draws as 3D meshes
(`rig::add`) or as a 2D cut-out (`rig::draw`).

```cpp
rig::Look look = rig::Look::toon();                   // toon / block (brick figure) / avatar / robot
look.hair = "hair.bun";                               // part keys: rig::parts::names()
look.arms("arm.soft").hands("hand.mitten");           // arm.rigid, arm.hose, arm.block (locked elbows)...
look.outfit = rig::Outfit::svg("characters/outfit-sailor.svg");   // drawn on outfit-template.svg
look.face = rig::svgFace("characters/face-pip.svg");  // or rig::simpleFace()

auto ch = std::make_shared<rig::Character>(look);
ch->motion.play(rig::clips::walk(), 0)                // crossfades; layer(clip, from, to, Mask::Upper)
         .play(rig::clips::cheer(), 6, 0.4);
ch->face.say(1.0, 2.6, "Hi!").expression(3, "happy", 0.2).look(4, { 0.4f, 0 }, 0.3);
ch->wear(5.0, rig::Look::block());                    // swap parts at 5 s: changed slots pop
ch->softness = [](double s) { return std::clamp(float(s - 2), 0.f, 1.f); };   // animate limbs

g3d::Object3D* root = rig::add(*scene, ch, 30);       // position/rotate `root` in its own up
rig::View2D v; v.yaw = 30; v.scale = 360; v.origin = { 480, 880 };
addRoot(c.roots, 0, 300)->fn = [ch, v](const Ctx& c, int t) { rig::draw(c, *ch, t / 30.0, v); };
```

- The face SVG names shapes by id: `eye-L/R`, `pupil-L/R`, `brow-L/R`, `mouth` (L is the
  character's left, on the viewer's right); variants `<id>-<expression>`, `eye-*-closed`,
  `mouth-A`..`mouth-H` (Preston Blair/Rhubarb). Any other id draws as is, or only under
  one expression if it ends in `-<expression>` (`blush-happy`).
- `FaceTrack::say` guesses mouth shapes from letters. Label it approximate on screen, or
  feed real cues with `rhubarb(...)`.
- Brick figures stay rigid because their parts' `locks` pin elbows/knees; the clips are
  shared.
- Keep the key light's `shadowExtent` near 1.5–2× the characters' height, or small
  figures get shadow acne.
- Draw 2D and 3D in either order in one frame (`g3d::render` flushes pending 2D first).

### Animals and other body plans

```cpp
auto dog = std::make_shared<rig::Character>(rig::animal("dog"));   // cat, horse, cow, giraffe, turtle
const rig::Build& b = dog->looks()[0].build;
dog->motion.play(rig::clips::gait(b, rig::Gait::Trot), 0);
g3d::Object3D* o = rig::add(*scene, dog, FPS);
o->up = [b](int t, g3d::Object3D& n) { n.position.x = rig::gaitSpeed(b, rig::Gait::Trot) * t / 30.f; n.rotation.y = 90; };
```

- An animal's +z is its front; turn it 90 degrees to walk it along +x.
- Gaits run in place, paws planted while down. Move the root by `gaitSpeed` (same
  cadence) and the paws stay put on the ground; `gaitCadence` is the natural rate.
- Make a new species from `QuadSpec` (lengths in metres, pitches in degrees); `species`
  picks the head, tail and coat parts. `Build::scaled` scales lengths, not angles.
- Joints are named (`b.plan->find("tail-2")`, `rig::joint(b, "paw-front-L")`); a plan's
  own joints layer only with `Mask::All`.
- In 2D the upper legs sort behind the barrel, so view animals side on (yaw 90) or three
  quarters.
- Apes (`chimp`, `gorilla`, `orangutan`) are humanoid builds: any humanoid clip works, and
  `clips::gait(b, Gait::Walk)` knuckle-walks (move by `gaitSpeed` as above).
  `clips::hang(b, barHeight)` hangs by both hands from a bar along x through z = 0;
  `clips::brachiate(b, barHeight, spacing)` swings bar to bar in place: the held bar slides
  back, so move the ape forward by `2 * spacing * brachiateRate(b)` per second and draw the
  bars `spacing` apart.
- Birds and dinosaurs (`chicken`, `duck`, `trex`; new ones from `BipedSpec`) have their own
  plan: `gait(b, Gait::Walk)` walks, any other gait runs, both moved by `gaitSpeed`.
  `rig::wings(b, pose, spread, flap)` layers wings on any pose (0 folded, 1 open; `flap`
  degrees up at the shoulder); `clips::fly(b)` flaps (in place: move the node along +z),
  `clips::glide(b)` soars; the jaw is the `"jaw"` joint (x > 0 opens it). A T. rex is
  12 m long: frame it from ~20 m.
- `clips::paddle(b)` swims any four-legged animal in place (a turtle sweeps its front
  flippers wide, a dog paddles); raise its node to the water line.
- Snakes and fish (`snake`, `fish`; new ones from `ChainSpec`, up to 38 segments) are a
  chain from `"body-0"` behind the head to `"tip"`. `gait` slithers or swims (Walk slower,
  any other gait faster), moved by `gaitSpeed`; a fish sits on the floor at rest, so lift
  its node to swim it. A snake's `"tongue"` joint at y = 180 is stowed, at 0 flicked out.

### Carrying: riders, passengers, climbers

```cpp
rider->motion.play(rig::clips::ride(rl.build), 0);   // astride, the hips at the root's origin
rider->mount(rig::saddle(horse));                    // hips on the back, stirrups, reins
for (auto ch : { horse, rider }) { auto* o = rig::add(*scene, ch); o->position = at; o->rotation.y = 90; }
```

- A `Mount` puts the rider's root on the carrier's `joint` (offset `at`, turned `rot` in that
  joint's frame) from `from` to `until`, easing over `blend`; the rider's own root motion
  rides on top. Both characters must share one node (or one `View2D`).
- `grips` reach hands and plant feet on carrier points (joint + local offset) after the
  mount -- reins and stirrups, a person's shoulders for a piggyback, a ladder's rungs.
- Hand-offs (a pilot from a titan's palm to its cockpit): add the next mount with `from`
  before the last one's `until`; they blend in the order added. Never mount in a cycle.
- In 2D each character sorts on its own, so the rider draws over its carrier: frame the
  rider's near side.
- `upright = true` keeps the rider level: it follows the joint's position and heading but
  not its tilt (a passenger standing on a palm or a rocking platform).

### Skinned bodies: a scanned or generated mesh on the skeleton

```sh
python tools/skin_bake.py body_tpose.glb assets/body.glb    # numpy + scipy; T-pose, +z front, < 65k verts
```

```cpp
const rig::Skin skin = rig::loadSkin(c.assets("body.glb"));  // reads body.glb.rig.json too
rig::Look l; l.build = skin.build;                          // the build fitted to the mesh
auto ch = std::make_shared<rig::Character>(l);
ch->motion.play(rig::clips::walk(), 0);                     // any humanoid clip, mounts, IK
rig::add(*scene, ch, skin);                                 // posed from ch every frame
```

- The baker fits a `Build` to the mesh (shoulders, arms, hands and the shoulders' depth
  `shoulderZ` measured; hips, knees and ankles from the legs and standard segment ratios),
  separates legs that a generator joined, and computes bone-heat weights. Clips must use
  the fitted build, or the joints will not sit inside the limbs.
- Skins use dual-quaternion skinning (`model->dualQuaternion`): shoulders and hips keep
  their volume when bent. Set it false for linear blending.
- Call `loadSkin` once per character: each call loads its own model, and a model holds
  one pose at a time.
- Check a bake with `raymotion_skin_view body.glb out_dir` (rest, walk, run, wave and sit,
  front and side, both blends).

### Acting: props, rides, furniture

```cpp
rig::Look l = rig::Look::toon();
l.build = rig::Build::adult();                         // furniture is real size; a toon perches
l.holdR = "prop.sign"; l.sign = "MORE\nBIKE LANES";    // \n breaks the line
auto m = std::make_shared<rig::Character>(l);
m->motion.play(rig::clips::protest(l.build), 0);
// Your own: IK on top of any pose, all in character space (+z front, left hand +x).
rig::Clip mine = [b = l.build](double s) {
    rig::Pose p = rig::clips::idle()(s);
    p[rig::Joint::Chest].x = 6;                       // parents first: the hands hang from them
    return rig::hand(b, p, rig::Side::Right, { -0.1f, 1.2f, 0.35f }, /*fingers*/ { 0, 0, 1 }, /*palm*/ { 1, 0, 0 });
};
```

- Props sit in the palm, so a pose holds a prop by placing the hand: `hand(b, p, side, at,
  fingers, palm)`. To grip a pole, point the fingers forward with the palm towards the
  pole and the thumb along it. To hold a phone, put the palm behind it, facing the eyes.
- `reach`/`plant` are exact when the target is in reach. Out of reach, the limb points
  straight at it. The pole is a direction given for the left side; the right side mirrors it.
- Rides hang from `Joint::Floor`, which ignores the pose's offset, so the body can bob and
  crouch while the board stays on the ground. The clips sink the hips just enough for a
  pushing foot to reach the floor. `skate` rolls towards the character's +x and `scooter`
  towards +z; move the root to match.
- Set a joint's parents (chest, neck) before placing a hand. Changing a parent afterwards
  moves the hand off its target.
- Seats: the office chair's top is 0.61 m, the restaurant chair 0.495 m, the sofa 0.64 m;
  desks and tables are 0.75–0.78 m. To use them, put the character's root on the floor
  under the seat, facing the way the chair faces. Convert targets such as the keyboard
  into that space (subtract the root's position, then undo its turn).

## Crowds, herds, flocks (`crowd::`, `rmtn/crowd.hpp`)

```cpp
crowd::World w;                                         // in build: bake once, keep the pointer
crowd::Group people; people.name = "people"; people.count = 40;
people.spawn = { 0, 0, -8 }; people.spawnSize = { 10, 0, 3 };
people.goal = [](double s, int i) { return Vector3{ (i % 8 - 3.5f) * 1.5f, 0, s < 5 ? 9.f : -9.f }; };
w.groups.push_back(people);
w.obstacles.push_back({ { 0, 0, 0 }, 1.5f });           // a fountain: a cylinder on the ground
w.to = 15;
crowd::CrowdPtr crowd = crowd::bake(w);
auto chars = crowd::cast(crowd, "people", [](int i) { return crowd::person(i); });
crowd::addAll(*scene, crowd, "people", chars, FPS);     // 3D; or crowd::draw(cx, ..., s, view) in 2D
```

- A boid flock is a simulation with state, so `bake` steps the whole world once at a
  fixed `dt`. It is seeded and updates every agent at the same time. Frames only sample
  the stored paths (`at`, `travelled`), so a frame is still a pure function of `t`. Bake in
  `build` and capture the `CrowdPtr` by value. Goals and predator paths must be pure
  functions of time. `w.to` must cover the film: sampling clamps outside it.
- Mediums:
  - `Ground` agents walk on y = 0. They move only where they face and turn at most
    `maxTurn`, so nobody slides sideways.
  - `Air` and `Water` agents move in 3D, never stall, and keep to `height0..height1`.
    Flyers bank into turns and pitch with their climb.
- Weights live in `Group::steer`: separation, alignment, cohesion, goal, wander, avoid,
  flee and bounds.
  - Keep `neighbour` several times `personal`, or separation pushes the agents out of each
    other's sight and the flock splinters. A tight flock uses about 10 and 0.6; strangers
    on a plaza use the default of 3.
  - Walkers with a goal stop flocking within about 5 m of it. A walker that has arrived
    stands still.
  - Walkers pass each other by predicting their closest approach, and they slide round
    obstacles and standing people.
- Threats: `flees` lists group names, or `Predator`s (a path the crowd can see, such as a
  car or the camera).
  - Within `panic` the agents speed up toward `maxSpeed`; alarm is full at half the
    distance.
  - Alarmed agents wheel round at full `maxTurn` and let go of their goal. They calm down
    over about 2.5 s.
  - Alarm spreads to flockmates, so a herd bolts together. Give a herd a `neighbour`
    radius wide enough to see across it.
  - `rest` gives calm herd agents seeded pauses for grazing.
- Pens: `penAt` and `penRadius` keep one group inside a vertical cylinder, such as fish in a
  pond or sheep in a fold. A soft wall turns them back even mid-flight, and the edge is
  hard. The world's bounds are one box for every group, so use a pen for a smaller space.
- A threat that strikes needs a far goal while it charges, because arrival braking slows
  any agent near its goal. Swap in the real stopping point afterwards. `crowd-demo`'s pike
  charges a goal 12 m out for one second.
- Gaits follow speed, with hysteresis:
  - humanoids idle, walk and run;
  - four-legged animals stand, walk, trot, canter and gallop;
  - birds, dinosaurs, snakes and fish walk and run;
  - birds in the air flap, or glide while descending.

  Each gait is time-warped by the ground covered, so a stride matches the distance. A
  humanoid walk also plants each footfall where the clip's ankle touched down, which
  measures under 1 cm of foot slide. Gait changes crossfade over 0.35 s.
- Cost: `cast(..., faces = 12)` gives faces to the first 12 agents only, because each face
  is a texture drawn every frame. `person(i)` and `herd(species, i)` choose outfits from a
  small cached palette, so the textures are shared. About 100 characters is the
  intended size.
- Culling: `crowd::add` sets `cullRadius` and `cullCentre` on each agent's holder, a sphere
  that holds every joint the agent ever reaches. A holder out of sight is skipped whole:
  no `up`, no canvases, no draw calls. "Out of sight" counts the shadow too: with a
  directional shadow light, the sphere is swept along the light down to `Scene::cullFloor`
  (default 0), so an agent just off screen still throws its shadow in. Culling turns itself
  off while any shadowing light is a spot or point light. Frames stay pure, because `up`
  assigns from `t`. It is opt-in per object: set `cullRadius` on your own objects with a
  generous sphere. `crowd-demo` renders pixel-identical with it on and off, and about 2.4
  times faster (the 2,742 items a frame drop to about 980).
- 2D: `crowd::draw(cx, crowd, group, chars, s, view)` turns each agent by `view.yaw` minus
  its own yaw, places it by projected position, and sorts back to front. The view's
  origin is where the world's (0, 0, 0) lands.

## Instancing (`g3d::Instances`, `crowd::addInstanced`, `crowd::addFlock`)

For hundreds of bodies a rig character is too dear: each builds its own geometry and costs
several draw calls. A baked body costs one draw call per pass for the whole group.

- **Bake.** `rig::bakeAnimated(look, clips, &where)` solves each clip frame by frame into one
  merged mesh of constant topology (a coarse grid; transparent and model prims are left out,
  colours come flat from the look). Positions and normals go to one RGBA32F texture
  (positions on top, normals below), read in the vertex shader with `texelFetch`.
  A mesh is limited to 65,535 vertices. The Look's outfit and face textures are dropped, so
  keep a few full rigs near the camera.
- **Instances.** `g3d::Instances` holds a list of `Instance` (position, yaw, pitch, bank,
  scale, frame, clip, shade). The shader blends the two nearest baked frames; per-instance
  data rides in the `w` of the instance matrix. Refill the list from `t` in `up`.
- **Crowds.** `crowd::addInstanced(scene, crowd, group, bodies, material, fps)` plays each
  walker's clip by distance travelled (stride matches the ground covered) and idles the
  standing ones; `addFlock` plays a flap cycle at a seeded rate. `walkCycle` and
  `flapCycle` return the phase actually played, for a pointer on a 2D strip.
- **Culling.** Each instance is tested with the same `inSight` as objects (frustum plus
  shadow footprint), so shadows of off-screen bodies stay. A pixel-parity test covers it.
- **Cost.** `zombie-horde`: 500 zombies and 1,000 bats render in about 21 ms a frame at
  1080p; the same horde as 500 rig characters took about 313 ms (13x). Zombie bake:
  2,385 vertices x 40 frames; bat: 149 vertices x 12 frames.
- **Limits.** Opaque materials only; the topology cannot change between frames.

## Water (`g3d::Water`, `Scene::water`)

A sea, lake or pool that works from above and below, with caustics on whatever is under it.

    scene->water = g3d::Water::calm();     // or choppy(), storm(); then change what you like
    scene->water.level = 0;
    scene->water.openDepth = 40;           // deep sea: opaque. 0 = clear, you see the floor through it

- **Waves.** Up to 8 `Water::Wave` (direction in degrees, wavelength, amplitude, sharpness,
  speed), summed as sharpened sines with deep-water speeds (`omega^2 = g k`). Waves move in
  seconds: set `water.fps` to the film's frame rate (default 30). Everything is a
  function of time, so frames stay pure. `Water::height(x, z, seconds)` and `slope(...)` give
  the CPU the shader's own surface, for a boat or a swimmer; `submerged(p, seconds)` tells
  whether a point is under it. The level is the mean for sharpness 1; sharper waves sit a little
  below it.
- **Above.** The surface reflects the sky or environment by Fresnel (so it is glass looking
  down and a mirror at a grazing angle), glints in the sun, and shows foam on the highest
  crests. Ripples smaller than a few pixels fade out so the horizon does not shimmer. It is
  drawn with the transparent objects, first, and writes no depth.
- **Below.** Anything lit under the surface (and anything seen through it) is tinted and
  darkened by `absorb` (per metre, red first) towards `deep`; the sky backdrop goes to `deep`
  too. The surface seen from below is Snell's window onto the sky, ringed by a mirror of the
  water.
- **Caustics.** A directional light that reaches a point under the surface is absorbed along
  its path and focused by the waves: the shader refracts the ray through the wave above the
  point and measures how the neighbouring rays spread (patch area over landing area), blurring
  with depth. It is the sun's light moved about, not added: the average brightness holds.
  `caustics` 0..1 scales it. It applies to Standard and Toon shading, and to instanced bodies.
  Objects whose sun is shadowed get none.
- **Limits.** The reflection is of the sky or environment only, not of the objects in the
  scene. Refraction does not shift what is seen through the surface. The water line on an
  object follows the wave height, but light is not bent by the object's own shadow.
  Unlit materials and particles are not tinted.

## Voxels (`voxel::`, `rmtn/voxel.hpp`)

    voxel::Grid g(64, 24, 64);                 // x, y (up), z cells; palette entries 1..255, 0 = empty
    g.palette[1] = { 214, 196, 150, 255 };
    g.box(0, 0, 0, 63, 3, 63, 1);  g.sphere(32, 8, 32, 6, 2);
    voxel::MeshOptions o;  o.size = 0.25f;  o.centre = true;
    voxel::MeshStats stats;
    scene->add(voxel::mesh(g, o, &stats), material);

- **Mesh.** `voxel::mesh` greedy-meshes a grid into one normal `Geometry` with palette colours
  in the vertex colours: faces between solid cells are dropped, coplanar faces of one colour
  merge into larger quads, and ambient occlusion is baked per corner (0..3, the quad's diagonal
  chosen so the shading does not streak; unevenly occluded cells are not merged). It lights,
  shadows, fogs, sits in water and culls like any mesh. `MeshStats` reports voxels, exposed
  faces, quads and triangles; `voxel::quads(grid)` gives the quads themselves, with no GPU.
  Grids that need more than 16-bit indices draw unindexed.
- **.vox.** `voxel::load` / `loadScene` / `loadModels` read MagicaVoxel files (scene graph with
  translations and the 24 axis rotations; hidden nodes skipped; only the first animation frame
  of a shape); `voxel::save` writes one model. Files are z-up and right-handed; here a model is
  y-up, (x, y, z) of the file becoming (x, z, -y). A bad file throws.
- **Animation.** `voxel::addFrames(scene, grids, material, hold, options)` shows one grid per
  `hold` frames from t, looping.
- **Cut.** `Material::clip` hides what is beyond a world-space plane and lights an edge band, for
  a front that sweeps through an object. Shadows are not cut.

## Gaussian splats (`splat::`, `rmtn/splat.hpp`; `g3d::Splats`)

    auto cloud = std::make_shared<const splat::Cloud>(splat::loadPly("assets/scan.ply"));
    auto splats = std::make_shared<g3d::Splats>();
    splats->cloud = cloud;
    g3d::Object3D* o = scene->add(splats);     // position, rotate and scale it like any object

- **Cloud.** Per splat a position, a Gaussian (scale = standard deviations along its own axes,
  a rotation), an opacity, a colour and optionally degree-1 spherical harmonics (colour that
  depends on the viewing direction). Builders: `sphereSurface`, `box`, `fromFunction`,
  `fromVoxels` (flat splats on the exposed faces of a grid), `merge`. `loadPly` reads a
  binary little-endian 3DGS file by property name (sigmoid on opacity, exp on scale, rotation
  normalised, `0.5 + 0.282 f_dc` for colour); a bare point cloud becomes small round splats.
  `savePly` writes the same format.
- **Drawing.** One instanced quad per splat. The vertex shader projects each splat's 3D
  covariance to a 2D ellipse (EWA, as in the paper), the fragment is `opacity * exp(-d^2 / 2)`.
  Splats are sorted far to near on the CPU each time the view changes (radix sort of those
  inside the frustum; 1M splats take about 26 ms a frame at 240x160, sort included) and
  blended over the scene; opaque objects in front hide them. Frames stay pure: the order is a
  function of the camera.
- **Look.** `Splats::look` has `scale` and `opacity` multipliers, `shDegree` (0 or 1), and a
  sweeping front (`clipNormal`, `clipOffset`, `clipBand`, `scatter`): splats past the front are
  gone and those within `clipBand` behind it fade and scatter, which is how a cloud dissolves.
  `up` assigns them from t.
- **Limits.** Splats are not lit, shadowed, fogged or tinted by water; a cloud is limited to 5
  million splats and is meant for about one million; there is no GPU sort and no tile
  rasteriser, so a dense captured scene much beyond that is out of reach. Spherical harmonics
  above degree 1 are ignored. Splats do not write depth, so they never hide each other (the
  sort decides) and depth of field and ink lines treat them as background. Blending is the
  usual back-to-front "over", which approximates the reference viewers' compositing.

## Rope and cloth (`physics::`, `rmtn/physics.hpp`)

Position-based dynamics: Verlet integration and iterated distance constraints at a fixed
step (`Params::substeps`, `iterations`, `fps`). A frame must be a pure function of `t`, so a
simulation is a **baked, lazily extended cache**: `rope.frame(f)` / `cloth.frame(f)` return
the particle positions for video frame `f`, stepping forward from the last cached frame
when `f` is new and reading the cache when it is not. Asking for frame 90 first gives the
same bits as stepping 0 to 90 in order. Copies of a `Rope` or `Cloth` share one cache, and
the returned references stay valid as the cache grows.

```cpp
physics::Params p;                                   // gravity, damping, substeps, iterations, fps
physics::Rope rope({0, 3, 0}, {0, 1, 0}, 24, p);     // from, to, segments
rope.pinEnd([](double s) { return Vector3{ std::sin((float)s), 3, 0 }; });   // an anchor on a path
rope.pin(0, [](double) { return Vector3{0, 3, 0}; });
rope.collide(physics::Collider::plane({0, 0, 0}, {0, 1, 0})).bend(0.4f);

physics::Cloth cloth(24, 16, 0.08f, {-1, 2, 0}, {1, 0, 0}, {0, 0, 1}, p);   // cols, rows, spacing, origin, axes
cloth.pinCorners().collide(physics::Collider::sphere({0, 1, 0}, 0.5f))
     .wind({ {1, 0, 0}, 3.f, 0.5f, 0.4f, /*seed*/ 7 });     // direction, strength, gust, gustHz, seed

scene->add(physics::ropeObject(rope, 0.03f, material));       // tube, follows t
scene->add(physics::clothObject(cloth, material));            // double-sided grid
```

- **Pins** (`pin`, `pinEnd`, `pinCorners`, `pinRow`) hold a particle at an absolute position
  from `t`, so a rope can be dragged along a path. **Colliders**: sphere, plane, capsule,
  box, each static or driven by `std::function<Vector3(double seconds)>`.
- **Cloth** has structural, shear and bend constraints (`stretch(k)`, `bend(k)` 0 to 1),
  deterministic gusting **wind**, optional **tearing** (`tear(ratio)`, off by default; the
  count of live constraints is `liveConstraintCount(f)`) and optional **self collision**
  (`selfCollision()`, off by default, a spatial hash at the particle radius `thickness`).
- `ropeMesh` and `clothMesh` are the CPU mesh builders (tube with end caps, cloth with
  recomputed normals); `ropeObject` / `clothObject` upload a dynamic mesh once and queue the
  per-frame vertices through `Geometry::update`, so topology is fixed.
- Cost: a 64x64 cloth at 4 substeps and 8 iterations costs about 9 ms per simulated frame
  (measured in `physics_tests`), paid once per frame because frames are cached.
- `Params::friction` (0 to 1) is the share of sliding motion a contact removes. Pin before
  the first `frame()` call: `pinCorners`, `pinRow` and `pinEnd()` hold a particle where it
  starts.
- Limits: no rope-to-cloth or rope-to-rope
  contact; collisions are position projections, not impulses, so fast thin colliders can be
  tunnelled through at low `substeps`.
